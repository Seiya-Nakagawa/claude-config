# セキュリティ規約

機密情報の取り扱いの基本方針はグローバル規約（`~/.claude/CLAUDE.md` 第2章）に定める。
本ファイルはそれを補足し、IaC・サーバーレス構成における具体的な扱いを定める。

## 1. 機密情報の管理

- API キー、パスワード、接続情報などの機密情報をコード内に直接記述することを**厳禁**とする
- 機密情報は環境変数（`.env` ファイルなど）で管理し、`.gitignore` に追加してリポジトリにコミットしない
- `.env`、`credentials.json`、`*.pem`、`*.key` などのファイルは絶対にコミットしない
- 認証情報の設定ファイル（`*.conf` 等）も同様に `.gitignore` の対象とする

## 2. IaC（Terraform 等）

- `secret` や `password` を含む変数には `sensitive = true` を設定する
- state ファイルにはリソースの機密値が平文で含まれるため、リモートバックエンドで管理し、
  アクセス権限を限定する。ローカルに残さない（[terraform.md](terraform.md) 参照）
- IAM ポリシーは最小権限の原則に従う。ワイルドカード（`*`）での広範な許可を避ける

## 3. サーバーレス・アプリケーション

- 機密設定値は SSM Parameter Store / Secrets Manager で管理し、関数からは**参照名**（環境変数経由）で
  アクセスする。値そのものをコード・環境変数定義に直書きしない
- 関数の実行用 IAM ロールは最小権限の原則に従う（権限定義は IaC 側で管理する）

## 4. ログ出力

- ログに機密情報（トークン・パスワード・個人情報等）を出力しない。
  必要な場合はマスキング処理を施す（[logging.md](logging.md) 参照）

## 5. AI による本番環境操作

AI が本番環境を直接調査・操作する必要がある場合は、管理者権限の認証情報をそのまま使わず、
権限を絞った専用ロールへスイッチして操作する。ロール名・アカウント・認証スクリプト等の
具体値はリポジトリ個別の `CLAUDE.md` に従う。専用ロールに与える権限は以下を原則とする。

- 調査に必要な**広範な読み取り**は許可する
- **本番リソースの構成変更は許可しない**（デプロイは常に CI/CD 経由とする）
- **機密値そのものの読み取り**（SSM パラメータ値・Secrets Manager 値・IaC state 等）は明示的に拒否する
