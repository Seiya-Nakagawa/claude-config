# Python 規約（サーバーレス関数アプリ向け）

言語共通のスタイル・命名規則・リンターは [coding-standards.md](coding-standards.md) 5章に従う。
本ファイルは、AWS Lambda 等のサーバーレス関数として動かす Python アプリ固有の規約を定める。
インフラ側（関数リソース・IAM・トリガー）の扱いは [lambda.md](lambda.md) を参照する。

## 1. ディレクトリ・ファイル構成

各アプリは `{アプリ基底ディレクトリ}/{アプリ名}/` 配下に以下の構成で配置する。
基底ディレクトリのパスはリポジトリ個別の `CLAUDE.md` に従う。

- `src/handler.py`: Lambda のエントリーポイント。ハンドラ関数は `lambda_handler(event, context)` とする
- `src/`: その他のアプリケーションコード（ハンドラから呼び出すモジュール）
- `tests/`: `pytest` によるユニットテスト（`test_*.py`）
- `requirements.txt`: 依存パッケージ。バージョンは固定（ピン留め）する
- `README.md`: アプリの概要・トリガー・環境変数・依存関係

## 2. 実装方針

- **ハンドラは薄く保つ**: `lambda_handler` は入出力の変換に徹し、ビジネスロジックは別モジュールに
  分離してテスト可能にする
- **ロギング**: `print` ではなく標準 `logging` モジュールを使用する。ログレベルは環境変数で
  制御できるようにする。出力内容は [logging.md](logging.md) に従う
- **例外処理**: 想定例外は捕捉してログ出力し、リトライ・DLQ の挙動を意識した戻り値／再送出を行う
- **冪等性**: イベント再送（SQS・EventBridge 等）を考慮し、可能な限り冪等に実装する
- **コールドスタート**: 重い初期化（クライアント生成・接続）はハンドラ外（モジュールスコープ）で
  行い、再利用する
- **型ヒント**: 積極的に付与する

## 3. 設定・シークレット

- 接続情報・API キー等の機密情報はコードに直接記述しない（[security.md](security.md) 参照）
- 設定値は環境変数で受け取る。機密値は SSM Parameter Store / Secrets Manager を参照する
- 環境変数・IAM ロール・トリガーの定義は IaC 側で行う（[lambda.md](lambda.md) 参照）

## 4. テスト

- ロジックは `tests/` で `pytest` によりユニットテストする
- AWS SDK 呼び出しは `moto` 等でモックし、外部依存に接続しない
- デプロイ前に必ずテストを実行し、通過を確認する
