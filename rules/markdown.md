# Markdown 記法ルール（markdownlint 準拠）

Markdown ファイル（`.md`）を作成・編集する際は、以下の markdownlint ルールに必ず従うこと。

## 見出し

- ファイルの最初の行はトップレベル見出し（`#`）にする（MD041）
- 見出しの前後には必ず空行を入れる（MD022）

## リスト

- リストの前後には必ず空行を入れる（MD032）
- ネストのインデントはスペース2つとする（順序付きリストを含む）（MD007）
- マーカー（`-`、`*`、`+`、順序付きリストの数字）の後に続くスペースは1つとする（MD030）
- 順序付きリストの番号は各セクションごとに `1.` から振り直す（MD029、style: ordered）
  - セクションをまたいで通し番号にしない
  - 正しい例:

    ```markdown
    ## 共通

    1. 項目A
    2. 項目B

    ## Terraform

    1. 項目C
    2. 項目D
    ```

## 空行

- 見出しとリストの間には必ず空行を入れる
- コードブロック（```）の前後には空行を入れる（MD031）
- ファイルの末尾は単一の改行で終了する（MD047）

## コードブロック

- バッククォート3つで囲み、言語名を指定してシンタックスハイライトを有効にする（MD040）

## ツール

- **リンター / フォーマッタ**: markdownlint。自動修正機能でインデントやスペースのスタイルを修正する
- markdownlint はルールベースの修正のみを行い、長い行の自動折り返しなどは行わない。
  規約で定めたルールを遵守すること

## リンク・パス表記

- ファイルパス・ディレクトリパスはバッククォートで囲む（例：`` `path/to/file.md` ``）
- 外部リンク（Google Sheets、Drive フォルダ等）は Markdown リンク形式で記載：`[表示テキスト](URL)`
- 対象外・廃止予定のドキュメントは打ち消し線で表記：`` ~~ファイル名~~ ``

## YAML フロントマター

- SKILL.md や agents の `---` フロントマターはルール対象外として扱う

## インラインHTML

- 原則としてインラインHTMLは使用しない（MD033）
- 例外として `<mark>` タグのみ許可する。設計文書で将来確定させる必要がある箇所を示す用途に限る
  （[document-standards.md](document-standards.md) 5章参照）
