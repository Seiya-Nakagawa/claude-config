# ログ出力規約

ログは、システムの動作状況を把握し、問題発生時の原因調査を迅速に行うための重要な情報である。

## 1. 目的

- **障害検知**: システムの異常を迅速に検知する
- **原因調査**: 問題発生時のデバッグや原因特定を効率化する
- **監査証跡**: セキュリティやコンプライアンスの要件を満たすための操作記録を残す

## 2. ログレベルの使い分け

| レベル | 内容 | 例 | 対応 |
| ------ | ---- | -- | ---- |
| ERROR | 対処がすぐに必要な状況 | API からの予期せぬレスポンス、リクエスト処理の失敗、例外のキャッチ | 監視対象とし、調査と修正が必要 |
| WARNING | 直ちにエラーとはならないが、潜在的な問題や注意喚起が必要な状況 | 非推奨 API の使用、設定値欠落によるデフォルト値の適用、リトライ可能な一時的エラー | 定期的なレビューと対応の検討 |
| INFO | システムの正常な動作を示す情報 | アプリケーションの起動・終了、リクエストの受付、重要な処理の開始・完了 | 本番環境で常に出力する |
| DEBUG | 開発およびデバッグ時にのみ使用する詳細情報 | 変数の値、関数の呼び出し、処理の通過点 | 本番環境では原則として出力を無効にする |

## 3. 出力時の注意点

- **個人情報を含めない**: 氏名、メールアドレス、パスワード等の個人情報や機密情報をログに含めない。
  必要な場合はマスキング処理を施す
- **構造化ログ**: 可能な限り JSON 形式などの構造化ログを採用し、後続の集計や分析を容易にする
- **コンテキスト情報**: リクエスト ID、ユーザー ID など、問題の追跡に役立つ情報を含める。
  エラーログにはスタックトレースを含めることを推奨する
