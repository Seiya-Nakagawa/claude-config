# コーディング規約

全リポジトリ共通の言語別コーディング規約。

## 1. 共通方針

- 各言語に適したリンター / フォーマッターを導入し、スタイルを統一する
- 手動でのフォーマットは原則禁止とし、リンターの自動修正機能を用いてコミット前に修正する
- 変数名・関数名などのコード識別子は英語を使用する。コメントは日本語で記述する
- **コメントに設計書・ドキュメントへの参照を書かない**: 「〇〇設計書 4.1節参照」のような参照は、
  ドキュメントの変更のたびにコードの修正が必要になるため禁止する。コードから設計書への
  参照は持たせず、設計書側からコードを追跡する
- **コードの説明となるコメントは積極的に残す**: 処理のまとまりの見出し、処理の意図、
  非自明な制約・回避策・注意点など、コードを読む人の理解を助けるコメントは書く・残す。
  既存のコメントを整理する場合も、削除の対象は次に限る
  - 設計書・ドキュメントへの参照（上記）
  - 変更履歴・作業日付・経緯（git 履歴・PR・Issue に委ねる）
  - コメントアウトした旧コード
- **マジックナンバーの禁止**: 意味の分からない数値を直接記述せず、名前付き定数として定義する
- **ネストの制限**: `if` 文やループのネストは原則3階層まで。深くなる場合は関数の切り出しや
  早期リターン（ガード節）でリファクタリングする

## 2. HTML

- **文法**: HTML5 の標準仕様に準拠し、セマンティックなタグ（`<main>`, `<nav>`, `<article>` 等）を適切に使用する
- **インデント**: スペース2つ
- **属性**: 属性値は常にダブルクォーテーション（`"`）で囲む。`<img>` タグには必ず `alt` 属性を指定する
- **フォーマッタ**: Prettier
- **リンター**: HTMLHint

## 3. CSS / SCSS

- **命名規則**: クラス名はケバブケース（`kebab-case`）。BEM（`.block__element--modifier`）の導入を推奨する
- **プロパティの順序**: 論理的な順序で記述する（構成 → 配置 → 見た目）
- **単位**: `rem` を基本とし、必要に応じて `px` や `%` を使用する
- **SCSS**: ネストは3階層までを原則とする
- **フォーマッタ / リンター**: Stylelint

## 4. JavaScript / TypeScript

- **変数の宣言**: 再代入しない変数は `const`、再代入が必要な場合のみ `let`。`var` は**禁止**
- **命名規則**:
  - 変数・関数: ローワーキャメルケース（`lowerCamelCase`）
  - クラス・型: パスカルケース（`PascalCase`）
- **非同期処理**: `async/await` を第一選択とし、`try...catch` でのエラーハンドリングを徹底する
- **モジュール**: ESM（`import` / `export`）を使用する
- **フォーマッタ**: Prettier
- **リンター**: ESLint

## 5. Python

- **規約**: PEP 8 に準拠する
- **命名規則**:
  - 変数・関数: スネークケース（`snake_case`）
  - クラス: パスカルケース（`PascalCase`）
  - 定数: アッパースネークケース（`UPPER_SNAKE_CASE`）
- **ドキュメンテーション**: 関数やクラスには Docstring（Google スタイル）を記述する
- **フォーマッタ / リンター**: Ruff（`ruff format` / `ruff check`）
- **型ヒント**: 積極的に付与する
- **サーバーレス関数アプリ**: ディレクトリ構成・実装方針・テストは [python.md](python.md) に従う
